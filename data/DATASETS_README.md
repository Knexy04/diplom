# Датасеты проекта

В архиве три датасета, использованных для обучения моделей.

## 1. adult_child_dataset (для YOLO26s)

**Источник:** Roboflow Adult-Child v4
https://universe.roboflow.com/projects-20qd2/adult-child

**Назначение:** Обучение детектора YOLO26s для прямой классификации adult/child.

**Обработка (выполнена нами):**

Исходный датасет с Roboflow содержал **3610 изображений** и **5 классов**:
- `Adult` (с большой буквы)
- `Child` (с большой буквы)
- `adult` (с маленькой)
- `kids`
- `robot`

Это связано с тем, что Roboflow собирает датасет из нескольких источников с разной разметкой, и классы дублируются. Перед обучением мы провели нормализацию:

1. **Объединение классов:**
   - `Adult` + `adult` → класс **0 (adult)**
   - `Child` + `kids` → класс **1 (child)**

2. **Удаление лишнего класса:** все 159 аннотаций класса `robot` были удалены — он не нужен для нашей задачи.

3. **Перезапись label-файлов** в формате YOLO (`<class_id> <x_center> <y_center> <width> <height>`, нормализованные координаты).

4. **Обновление data.yaml**: `nc: 2`, `names: ['adult', 'child']`.

**Финальная структура:**
```
adult_child_dataset/
├── data.yaml
├── README.dataset.txt
├── README.roboflow.txt
├── train/
│   ├── images/  (3006 .jpg)
│   └── labels/  (3006 .txt в YOLO формате)
├── valid/
│   ├── images/  (434 .jpg)
│   └── labels/  (434 .txt)
└── test/
    ├── images/  (170 .jpg)
    └── labels/  (170 .txt)
```

**Train/Valid/Test split:** 3006 / 434 / 170 = 3610 изображений.

**Распределение классов в train:** 2226 объектов adult, 2768 объектов child.

## 2. UTKFace (для MobileNetV2)

**Источник:** https://susanqq.github.io/UTKFace/
(зеркало с прямой загрузкой: https://www.kaggle.com/datasets/jangedoo/utkface-new)

**Назначение:** Обучение MobileNetV2 для бинарной классификации возраста по лицу.

**Обработка структуры файлов:** не проводилась — все 23 708 фото лежат в одной папке `UTKFace/`.

**Формат имён файлов:** `[age]_[gender]_[race]_[date&time].jpg.chip.jpg`

Например: `25_0_0_20170117171516040.jpg.chip.jpg` означает возраст 25 лет, мужчина, белый.

**Обработка во время обучения** (выполнена в `train_age_classifier.py`, не модифицирует файлы датасета):

1. **Извлечение возраста** из имени файла регулярным выражением.
2. **Бинаризация:** возраст < 12 лет → метка `child` (0), ≥ 12 лет → `adult` (1).
3. **Объединение** с FGNET в общую обучающую выборку.
4. **Oversampling** класса `child` для балансировки (детских лиц в UTKFace значительно меньше, чем взрослых).
5. **Стратифицированное разбиение** 80% train / 20% valid с сохранением баланса классов.
6. **Аугментации** имитируют условия видеонаблюдения: JPEG-компрессия (q=30-80), motion blur, гауссов шум, downscale, ±30% яркости и контраста, ±15° поворот, горизонтальное отражение.

## 3. FGNET (для MobileNetV2)

**Источник:** https://yanweifu.github.io/FG_NET_data/
(зеркало: https://www.kaggle.com/datasets/anastasiapavlova/fgnet)

**Назначение:** Дополнительный датасет для обучения MobileNetV2 — увеличивает представленность детских лиц.

**Обработка структуры файлов:** не проводилась.

**Структура:**
```
FGNET/
└── FGNET/
    ├── images/      (1002 .jpg, имена вида 001A02.JPG)
    ├── points/      (landmark файлы — мы не используем)
    └── Data_files/  (вспомогательные файлы)
```

**Формат имён файлов:** `[id]A[age].JPG`

Например: `001A02.JPG` означает человек id=001, возраст 2 года.

**Обработка во время обучения:** аналогична UTKFace — извлечение возраста из имени, бинаризация по порогу 12 лет, объединение с UTKFace.

## Что НЕ входит в архив

- **COCO** — на нём предобучены базовые веса YOLO26s.pt и YOLO26n-pose.pt. Подтягивается автоматически фреймворком ultralytics, отдельно не скачивался.
- **ImageNet** — на нём предобучен MobileNetV2. Подтягивается автоматически через torchvision.
- **Тестовые видео** (sample.mp4, IMG_8079.mp4, kids_park.mp4 и т.д.) — это материалы для проверки готовой системы, не для обучения моделей.
